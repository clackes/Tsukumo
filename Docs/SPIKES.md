| 7 | Duo: lid-angle sensor over HID and frame capture on real MacBooks | Phase B, first step of Duo | **Partial, leaning go** (MacBook Air 13" M4 only, `Mac16,12`, macOS 27.0.1). **Sensor:** `AppleSPUHIDDevice` named `las`, usage page 0x20 / usage 0x8A, found with `IOHIDManager` read-only, **no TCC permission**. `IOHIDDeviceGetReport` of feature report ID 1 returns 3 bytes (ID, angle as uint16 little endian in whole degrees): 94° with the screen open. Cost of one read 0.4-0.7 ms. **Actual rate:** the value changes at most every ~100 ms (median 99.9 ms, minimum 25 ms) and with 1° resolution, even when reading at 120 Hz; asynchronous input reports arrive at ~1 Hz (15 in 15 s), so they are useless for following the motion. `ReportInterval` already reads 8000 µs and does not change the result. Consequence: sample at 30-60 Hz only during the motion and interpolate/predict between samples (visible lag of ~100-150 ms to hide). **Detecting the start of the motion without polling** remains open: the ~1 Hz input report is the only event, with up to 1 s of latency. **Capture:** `SCScreenshotManager.captureImage` of the display (1710×1112) succeeded in 114 ms cold, with the Screen Recording permission already granted to the test process. **Metal overlay tried on 12 Nov 2026 on the user's Mac:** frame 16 ms, drawing 0.5-2 ms; with the eye fixed in the world and the desktop anchored in space the image stretches (the glass foreshortens), so the default is \"Movimento\" 0%: desktop still on the screen, only increasing blur and dimming. **Problems found and fixed:** fold held with the lid still below the threshold (lock-up), ±1° jitter that prevented detecting rest, short jolts that started the animation (now an 8° dead zone and a minimum duration of 0.2 s). **Choices:** frame frozen with `SCScreenshotManager` (114 ms) instead of a stream; check every 100 ms at rest (exception to the "events before polling" rule, ~0.5 ms per read, stopped when the display is off) because the kernel event arrives at ~1 Hz; angle prediction between samples; fuses that remove the overlay if the lid has been still for 1.5 s or the session lasts 30 s. **Not tried:** sleep and wake with the lid closed, capture indicator and re-prompt, other models and macOS 26, measured energy cost. Functional reference: Mac Duo (macduo.co.uk, closed source, paid, no code to reuse) declares the same scheme: reading about 120 times per second while the lid moves, capture only while moving, Screen Recording permission, MacBook Pro 14/16" 2019-2026 and Air 13/15" 2022-2026, excluding Air M1 and Pro 13". | 12 Nov 2026 | – |
